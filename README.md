# 六人掼蛋

按《六人掼蛋小程序 PRD v1.0》开发，发布目标现已调整为 **微信小游戏**。六人、三副牌、每人 27 张、隔位组队。根工程使用 `compileType: game`，入口为 `minigame/game.js`，以横屏 Canvas 绘制大厅和牌桌。保留 Web 原型与旧小程序页面作为参考；正式发布仍需真实小游戏账号验收、合法域名与后端部署。

## 微信小游戏（当前发布目标）

底部手牌采用居中的单排重叠大牌面，随手牌数量自动调整间距，27 张全部可见；选牌向上抬起，滑选按最上层牌面命中。大小王以红色/黑色竖排 `JOKER` 区分，桌面出牌同步使用此显示方式。此布局保留理牌分组和组号，不影响真实牌值与服务器判定。

小游戏牌桌新增「一键理牌」与「调整」：自动按天王炸、普通炸弹、三王炸、同花顺和其他组合优先整理，每张实体牌只归入一个组，剩余牌单列。手牌显示组号和分组底线；分组面板可点选整组、前移/后移、拆组，也可在下方手牌点选或滑选后「选牌成组」。不合法的牌型会提示，不能强行成组。按点数/花色排序可退出分组排列。自动方案是启发式建议，不代表全局最优打法。

分组只影响当前客户端的手牌展示，不发送出牌动作、不读取其他玩家手牌。出牌和贡还贡后清理失效牌并补入新牌，新一局重置；前后台重连保留当前内存中的分组，彻底关闭小游戏后需重新理牌。更新本功能只需重新编译/上传小游戏客户端，无需更新 VPS 后端。

```bash
npm install
npm run build:game
npm run check:game
npm run dev:server
```

若本机 npm 启动器损坏，可将命令中的 `npm` 换为 `corepack npm`。微信开发者工具导入项目根目录 `E:/learning/guandan-six`，选择小游戏，确认 AppID 为你有权限的小游戏账号。已有工程需关闭后重新打开以读取新的 `miniprogramRoot: minigame/`。现在提供真正的 `game.js` 与 `game.json`，不再使用 WXML 或 Page 作为小游戏入口。

`game-src/` 是手写 TypeScript 源码，`npm run build:game` 类型检查后将客户端、请求连接封装和共享规则打包为单文件 `minigame/game.js`。构建产物随 Git 提交，克隆后可直接导入；修改源码后必须重新构建。后端仍是独立的 Node.js 服务，不能随小游戏客户端上传到微信。

小游戏提供微信/游客登录、昵称与服务地址输入、建房及配置、六位房号加入、分享 query 邀请、上次房间恢复、五机器人体验局；横屏牌桌支持六席隔位组队、准备/开局/换座、两排手牌点选和滑选、排序/清空/提示/出牌/不出、托管、记牌器、贡还贡、排名结算及续局。规则和战绩以可翻页面板展示。隐藏时关闭 socket 与计时器，返回前台重新获取快照；Canvas 按屏幕安全区域缩放，避免刘海区域遮挡。

小游戏默认后端为 `https://gd6.super-idol.com`；本机调试可在大厅「连接设置」切换到 `http://127.0.0.1:3001`，真机局域网调试填写电脑 IP。已有保存地址优先于默认值，联网测试时需检查此设置。微信登录的 `WECHAT_APPID` 必须匹配小游戏 AppID，密钥只放后端环境变量。游客身份与房间仍按服务地址隔离。

验证包含独立小游戏打包、无 DOM / Page / App 环境启动、分享入房、准备、提示出牌、触点换算和前后台恢复。Canvas 模拟测试不等于微信模拟器或真机验收；真实微信登录、分享接收、公网重连、平台审核及发布资格尚未验收。工程入口参考 [微信官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)。

2026-09-10 验证：全项目 45 项测试通过，其中 6 项验证小游戏构建产物、无 DOM 启动、邀请入房、准备、滑选/提示/出牌、前后台恢复、安全区坐标、还贡选择、结算续局和房间开关。小游戏打包、Web 生产构建和旧小程序编译均通过。使用浏览器 Canvas 适配层连本地真实后端，检查了游客大厅、体验局六席及 27 张手牌；该适配层仅作本地验收，不包含在小游戏包中。牌桌右上角预留微信原生胶囊菜单空间。

## 运行

VPS 联网测试域名为 `gd6.super-idol.com`，小游戏默认连接 `https://gd6.super-idol.com`。Docker 部署、自动 HTTPS/WSS、持久化、更新和备份见 [VPS 部署说明](deploy/README.md)。`compose.yaml` 默认只启动应用；空闲 VPS 加 `--profile https` 才启用 Caddy，已有网站应复用原反向代理。

需要 Node.js 22.12+（开发验证环境为 Node.js 24）。

```bash
npm install
npm run dev
```

打开 http://localhost:5173。首次输入昵称，以游客身份创建房间或输入六位房间号加入。房间分享链接形如 `http://localhost:5173/?room=123456`；和其他设备联机时请使用电脑的局域网 IP，所有客户端访问同一服务地址。

- 六名玩家需使用六个独立浏览器身份（不同设备、浏览器或隔离的浏览器配置），同一浏览器中的标签页共享游客身份。
- 六人全部准备后由房主开始。队伍按座位 `A B A B A B` 排列，自己的位置始终显示在底部。
- 「体验一局」由一位真实玩家和五个明确标识的体验机器人组成。机器人只用于玩法验证，不代表高级 AI。
- 页面刷新会恢复游客令牌与房间，WebSocket 重新认证后恢复自己的手牌。
- 正在进行的牌局退出时保留座位，按房间配置托管；需返回原房间，不能同时参加另一局。

构建与单进程运行：

```bash
npm run build
npm start
```

构建后服务端同时提供前端和接口，访问 http://localhost:3001。可设置 `PORT`、`DATA_DIR`；`ENABLE_DEMO=false` 可关闭体验桌。Vite 开发服务把 `/api` 和 `/ws` 代理到 3001。

- 联机：WebSocket 各玩家独立视图、客户端仅持有自己的手牌、操作版本校验、拒绝重复/过期操作、超时操作、托管、断线恢复。

## 规则解释（6P_V2）

2026-09-10 按最新约定启用 6P_V2。新建房间默认 V2；已有 V1 房间继续按原来的 +1/+2/+3 和普通三王规则运行，不在局中改判。要体验新规则请新建房间。

| 项目 | 当前实现 |
| --- | --- |
| 一局结束 | 第五位玩家出完后，最后一人记为末游；不在一队全部出完时提前结束 |
| 升级 | 头游队获胜；末尾连续 3 / 2 / 1 名对手分别 +4 / +3 / +2；末游为胜方则 +1 |
| 级牌 | 大王 > 小王 > 当前级牌 > A > K > … > 2；级牌在顺子中按自然点数参与 |
| 顺子边界 | A2345 和 10JQKA 合法，QKA23 不合法；三连对支持 AA2233、QQKKAA，钢板支持 AAA222、KKKAAA |
| 逢人配 | 红桃级牌可替代普通点数及同花顺所需花色，不可替代王；单出仍是级牌；有多个解释时服务器选择能压过当前牌的合法解释 |
| 炸弹 | 天王炸 > 12 炸 > … > 7 炸 > 三大王炸 > 三小王炸 > 6 炸 > 同花顺 > 5 炸 > 4 炸。普通同点炸弹最多 12 张，可含逢人配 |
| 王 | 三大王、三小王单独打出为三王炸；3 大王 + 3 小王为天王炸。逢人配不得替王；其他混合王炸无效。同种王仍可成对、作为三带二中的天然一组 |
| 接风 | 出完者最后一手无人压时，其顺时针最近的未出完队友首出；无存活队友则顺时针下一位首出 |
| 进贡配对 | 按升级数确定进贡人数、上限 3 人（+4 按三贡）；从败队按完赛名次倒序取贡方，配给胜队名次最靠前玩家；避免胜队含末游时向队友进贡 |
| 贡牌 | 最大的非逢人配牌，同大允许选择任意一张；贡牌最大者下一局首出，同大按贡方配对顺序 |
| 还贡 | 2–9 的非级牌；如没有，允许最小非逢人配牌；只有逢人配时允许最小牌，避免贡还贡死锁 |
| 抗贡 | 单贡者至少 2 张大王；双/三贡的败队合计 3 张大王；抗贡时上局头游首出 |
| 打到 A | 等级到 A 后还需该队在自身 A 级且当前打 A 的牌局获胜，不能从 K 升到 A 直接结束 |
| 固定局数 | 打满约定局数后停止，结束页展示最后一局头游队、双方等级及整场统计；尚未额外定义按总等级判定整场冠军的规则 |
| 提示 | 按合法牌型生成代表组合，同点数的等价实体牌不穷举排列；优先普通组合，尽量保留炸弹、逢人配和王 |
| 超时 | 默认 30 秒，可设 15/60 秒或不限时；允许托管时超时进入托管，关闭主动托管时仍执行本次超时安全操作 |

`RuleConfig` 位于 `shared/types.ts`，房间创建接口在服务端校验版本、人数、牌数、局数和开关范围。

V2 回归覆盖全部 720 种完赛顺序、完整炸弹大小链、王炸不可配牌、提示包含天王炸、服务端王炸计数、升四级后三贡和 V1 兼容。最大炸弹统计仍按实体牌张数记录，因此「最大张数」不代表王炸的牌力排名。

V2 验证结果：49 项测试通过；小游戏、Web 构建及小程序原生编译通过；1,000 次发牌和 30 局完整模拟通过，包含跨局升级、贡还贡、抗贡、牌数守恒及私有手牌隔离。

## 项目结构

```text
shared/cards.ts       纯规则、牌型和提示，前后端共享
shared/types.ts       规则配置、状态模型、公开视图及操作协议
server/game.ts        服务端对局状态机与事务式操作验证
server/index.ts       HTTP / WebSocket、身份、持久化、战绩
src/                  React 界面与客户端连接
miniprogram/          原生首页、牌桌、规则、战绩、连接设置及微信请求/连接封装
scripts/sync-shared.ts  将同一规则源同步到小程序编译根目录
scripts/check-miniprogram.ts  微信官方 WXML/WXSS 编译与页面完整性检查
tests/                规则、状态机、真实网络与恢复测试
scripts/simulate.ts   随机发牌与完整牌局压力验证
```

客户端的选牌合法性检查仅为按钮反馈。最终出牌解释、大小、回合、排名、胜负和贡还贡全部由服务端重新判定。服务端不会将其他玩家手牌放入公开视图；无权查看房间的身份也无法订阅其 WebSocket。

## 当前边界

- 原生页面和微信登录接口已接通，分享使用微信原生分享入口和房间邀请路径；尚未完成微信开发者工具模拟器、真实账号授权、分享接收与真机手势验收。游客身份与微信身份没有绑定。
- 后端使用 Node.js + TypeScript + `ws`，前端使用 React + Vite；尚未引入 PRD 建议的 NestJS、PostgreSQL、Redis。JSON 存档用于单进程开发，不能支持多实例并发写入。
- 尚未验证 100 房间 / 600 人并发、跨公网延迟、3 秒恢复 SLA 或真机小程序性能；房间容量上限不是负载测试结论。
- 暂无语音、商城、排位、充值或高级 AI。页面视觉以可操作组件为准，图片概念生成服务网络失败，因此使用代码绘制标准牌面，不依赖外部生成图片。
- 本开发版的游客令牌保存在浏览器本地存储，不应直接作为正式账号系统上线。生产接入需微信服务端换取身份、HTTPS/WSS、数据库迁移与部署监控。

微信服务端预接入需通过环境变量设置 `WECHAT_APPID` 和 `WECHAT_SECRET`，不要提交密钥。未配置时接口返回 501；Web 客户端仍使用游客身份。历史存档可恢复已知局数和出牌统计，旧版本未记录的个人头游等明细无法补算。

技术参考：[Vite 文档](https://vite.dev/guide/)、[ws 官方仓库](https://github.com/websockets/ws)、[Node.js Crypto](https://nodejs.org/api/crypto.html)。

## 旧微信小程序页面（保留参考）

以下为旧小程序客户端说明，不是当前小游戏的导入方式。根工程已经切到小游戏；旧页面保留在 `miniprogram/`，供回归测试和复用请求、规则展示逻辑。若单独运行旧客户端，需要另建小程序工程配置，指定 `miniprogram/`、小程序 AppID 和 TypeScript 编译插件。

```bash
npm install
npm run check:mini
npm run dev:server
```

首页提供微信登录、游客进入、创建房间、六位房号加入、返回房间和五机器人体验桌；牌桌提供准备、房主换座/组队、出牌/不出/提示、两排手牌滑选、排序、贡还贡、托管、记牌、结算及原生房间邀请。规则页解释 6P_V2；战绩页显示服务端统计与排名；连接设置按服务地址隔离身份和房间。服务端始终判定最终操作，不向小程序发送他人手牌。

默认接口地址在 miniprogram/config.ts，为 https://gd6.super-idol.com。本机开发可在连接设置改为 http://127.0.0.1:3001，真机局域网开发需填写电脑 IP，并确保手机可访问服务。体验版与正式版必须配置 HTTPS 请求域名和对应 WSS socket 合法域名；客户端只允许开发版使用本机或私有网段 HTTP。连接测试检查已保存地址，输入新地址后需先保存。

微信登录通过 wx.login 获取临时代码，再由服务端换取身份；服务端环境变量 WECHAT_APPID 应与小程序 AppID 一致，WECHAT_SECRET 仅保存在服务端。未配置时页面展示接口错误，用户可主动选择游客进入。当前登录测试使用模拟微信接口，不代表真实账号授权已验收。

共享规则只修改 shared/，运行 npm run sync:mini 更新 miniprogram/shared/，不要手工修改生成副本。小程序仅调用牌型识别、排序、提示展示；洗牌和发牌仍在服务端执行。页面隐藏时关闭连接和计时器，回到牌桌时重新获取快照并认证；过期连接事件被丢弃，动作冲突后重新同步。

```bash
npm run check:mini
npm run check:mini:native
npm test
npm run build
```
